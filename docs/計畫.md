# NestFlow MVP 實作計畫

> 版本：v1.3  
> 架構：Thin Backend 主導、Dify 輔助  
> 開發方式：一次只完成一個模組，完成後停止，等待使用者測試

---

## 1. 專案目標

NestFlow 是一個以手機 PWA 與 LINE 為主要入口的單人個人管家。

第一版只實作：

- LINE Login。
- Workspace。
- 最小家庭共享機制。
- PWA 記帳。
- LINE 記帳。
- Dify 自然語言解析。
- PWA 行程。
- LINE 行程。
- 提醒通知。
- 最小 Discord 整合。

其他能力僅保留擴充空間，不在本階段設計或實作。

---

## 2. 核心原則

1. Thin Backend 負責安全、資料、權限、確認、排程與真正執行。
2. Dify 只負責自然語言理解與結構化輸出。
3. Dify 不直接讀寫正式資料庫。
4. Dify 不決定使用者與 Workspace。
5. 所有寫入動作都必須由後端驗證。
6. LINE 自然語言寫入前必須要求使用者確認。
7. PWA 表單不呼叫 Dify。
8. 固定格式指令優先，不符合時才呼叫 Dify。
9. 一次只做一個模組。
10. 完成一個模組後立即停止。

### 4.3 機密資料處理補充

以下高敏感欄位必須以 AES-256-GCM 加密後才可存入資料庫：

- LINE ID Token 與 Access Token。
- `external_identities.external_subject`。
- Discord Token。

以下欄位只保存不可逆雜湊：

- `workspace_invitations.code_hash`。
- `sessions.token_hash`。

一般業務欄位（金額、分類、備註、行程標題）不加密，以維持查詢與彙總能力。

加密主金鑰規則：

- 以 `Encryption:Key` 設定於 `appsettings.json` 區段，實際值只存在 `appsettings.Development.json` 或環境變數。
- 一律透過 `IOptions<EncryptionOptions>` 注入，程式不得直接讀取設定字串。
- 金鑰不得進入版控，也不得寫入容器映像。

## 7. Workspace 與最小家庭機制

第一版一個使用者可建立多個 Workspace。

例如：

- 個人。
- 家庭。
- 工作。
- 研究。

Workspace 分成：

- 個人 Workspace：只有建立者可使用。
- 家庭 Workspace：可透過短期邀請碼加入其他 LINE Login 使用者。

### 7.1 基本規則

1. 每筆業務資料必須包含 `workspace_id`。
2. `user_id` 只能由後端登入身分取得。
3. 使用者只能存取自己建立或已加入的 Workspace。
4. 前端傳入的 `workspace_id` 必須由後端重新驗證 Membership。
5. LINE 預設寫入使用者指定的預設 Workspace。
6. 第一版不支援從 LINE 指令切換 Workspace。
7. 家庭成員加入同一 Workspace 後，共用該 Workspace 的記帳、行程與提醒。

### 7.2 建立家庭 Workspace

建立家庭時：

1. 使用者建立一個 Workspace。
2. 將 Workspace 類型設為 `family`。
3. 建立者自動加入該 Workspace。
4. 建立者可以產生短期邀請碼。

### 7.3 短期邀請碼

邀請碼規則：

- 有效期限 24 小時。
- 每組邀請碼只能成功使用一次。
- 邀請碼只保存雜湊，不保存明文。
- 邀請碼不可作為登入憑證。
- 邀請碼不可作為資料加密金鑰。
- 邀請碼使用成功後立即失效。
- 過期邀請碼不得使用。

加入流程：

```text
家庭建立者產生邀請碼
→ 將邀請碼傳給家庭成員
→ 家庭成員使用 LINE Login 登入 PWA
→ 輸入邀請碼
→ 後端驗證邀請碼
→ 建立 Workspace Membership
→ 成員加入相同 Workspace
```

### 7.4 第一版權限

第一版只有兩種狀態：

- 建立者。
- 成員。

建立者可以：

- 產生短期邀請碼。
- 查看成員列表。
- 移除成員。
- 修改 Workspace 名稱。
- 刪除 Workspace。

成員可以：

- 查看共同 Workspace。
- 新增、修改及刪除共同記帳。
- 新增、修改及刪除共同行程。
- 建立及取消共同提醒。
- 主動離開 Workspace。

第一版不實作：

- Admin。
- 自訂角色。
- 細粒度權限。
- 加入審核。
- 多階段邀請。
- 單筆資料可見性。
- 個別成員唯讀模式。

以上僅保留擴充空間。

## 9. Dify Workflow

Workflow 名稱：

```text
personal-assistant-intent-parser-v1
```

輸入：

- `message`
- `locale`
- `timezone`
- `current_time`
- `allowed_intents`
- `schema_version`

固定輸出：

```json
{
  "schemaVersion": "1.0",
  "workflowVersion": "personal-assistant-intent-parser-v1",
  "intent": "create_expense",
  "confidence": 0.95,
  "requiresConfirmation": true,
  "data": {
    "amount": 120,
    "currency": "TWD",
    "category": "餐飲",
    "note": "午餐",
    "occurredAt": "2026-08-03T12:00:00+08:00",
    "title": null,
    "description": null,
    "startAt": null,
    "endAt": null,
    "content": null,
    "triggerAt": null
  },
  "missingFields": [],
  "reply": "準備新增午餐支出 120 元。"
}
```

後端必須拒絕：

- 非法 JSON。
- 未知 Schema Version。
- 未知 Workflow Version。
- 非白名單 Intent。
- 金額格式錯誤。
- 日期格式錯誤。
- 必要欄位缺失。
- 低信心結果。
- 含 `user_id`、`workspace_id`、SQL、URL 或 Script 的結果。

## 10. Dify 串接方式

後端使用：

```csharp
public interface IAssistantProvider
{
    Task<AssistantResult> ParseAsync(
        AssistantRequest request,
        CancellationToken cancellationToken);
}
```

第一版實作：

```text
DifyAssistantProvider
```

流程：

```text
LINE 訊息
→ 驗證 Signature
→ 找到本地 User
→ 找到預設 Workspace
→ 固定格式解析
→ 未命中才呼叫 Dify
→ 驗證 Dify JSON
→ 建立 Pending Action
→ 回覆確認訊息
→ 使用者確認
→ 後端寫入 SQL Server
```

PWA 表單不呼叫 Dify。

## 11. 固定格式

以下訊息不呼叫 Dify：

```text
記帳 午餐 120
支出 交通 60 捷運
收入 薪資 50000
確認
取消
```

目的：

- 降低 Token。
- 降低延遲。
- Dify 故障時仍可使用。
- 提高明確指令穩定性。

## 14. 最小測試

每個模組只做：

- 1 個成功 Unit Test。
- 1 個失敗 Unit Test。
- 1 個核心 Integration Test。

不可省略：

1. LINE Login 非法 `state` 被拒絕。
2. 無效 ID Token 被拒絕。
3. User A 無法存取 User B。
4. Workspace A 不回傳 Workspace B。
5. 非 Workspace 成員無法存取該 Workspace。
6. 過期或已使用邀請碼不可加入 Workspace。
7. LINE Signature 錯誤時拒絕。
8. 同一外部事件不重複處理。
9. Dify 非法 JSON 不寫入資料。
10. Dify 未知 Action 不執行。
11. Pending Action 只能由原使用者確認。
12. 已成功提醒不重複發送。
13. Dify 停機時固定格式仍可使用。

## 17. Token 控制規則

1. 一次只讀取目前模組相關檔案。
2. 不重複掃描整個 Repository。
3. 不提前設計未來功能。
4. 不建立未使用的抽象層。
5. 不為未實作功能建立介面。
6. 不增加大量測試。
7. 不建立大量 UI 元件測試。
8. 不自行新增 Agent，如需要請詢問。
9. 不重構無關程式碼。
10. 完成一個模組後立即停止。
